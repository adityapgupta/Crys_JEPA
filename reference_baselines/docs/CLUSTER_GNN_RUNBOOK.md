# Cluster runbook: reference-utility GNN (1B + 2A)

This runbook prepares and runs the clean reference-selection experiment on a
remote Linux cluster. It does not run the experiment on this machine.

Design: [gnn_reference_selection.md](gnn_reference_selection.md).

Full runtime is **not measured on cluster hardware**. The job script requests 48
hours (`long` partition, 2-day limit) for the whole job (all 36 runs). Measure
one graph before you submit the full job.

Reference measurement on one 8-thread development CPU (macOS, not the cluster):

- one GCN epoch on all 141,126 fit rows: about 49 s, plus validation;
- one pool build on 37,438 validation rows: about 10 s;
- one complete run (20 epochs) should take about 16 to 20 min;
- all 36 runs should take about 10 to 12 h, less with early stopping.

These numbers are indicative. The cluster CPU and early stopping will change
them.

## 2. What to copy outside Git

Copy the files in `reference_baselines/cluster/cluster_inputs.txt` with
`rsync`. They are large. The candidate embedding array alone is about 634 MB.

From the local repository root:

```sh
rsync -av --files-from=reference_baselines/cluster/cluster_inputs.txt \
  ./ user@cluster:/path/to/Crys_JEPA/
```

`--files-from` keeps relative paths. Create the target directory tree on the
cluster first if some parent folders do not exist.

`candidate_labels.csv` is needed for evaluation only. Do not open it before the
evaluation step. The code blocks early reads of this file by construction, but
you must also keep the order of steps.

### Duplicate tables

Two options:

1. Copy the precomputed tables (small, recommended):
   - `reference_baselines/results/validation_duplicate_pairs.csv`
   - `reference_baselines/results/reference_gnn/reserved_duplicate_pairs.csv`
   - `reference_baselines/results/reference_gnn/reserved_duplicate_audit.json`

   Set `STAGE=prepare` with `BUILD_RESERVED_DUPLICATES=0` (the default). The
   script passes `--reuse-duplicates` to `--prepare`.

2. Let the cluster rebuild the reserved table from the release relaxation data.
   This needs the 859 MB release folder at
   `reference_baselines/data/release/exp_logs/base/mp_20/eval/`. It also needs
   `pymatgen`. Set `BUILD_RESERVED_DUPLICATES=1`.

Option 1 is smaller, but the duplicate check is then based on the local
structures. Record this limit in the report.

## 4. Python environment

Do not install on the login node. Build the environment with the Slurm job
`install.sh` (CPU-only torch, temp files in `$HOME/tmp`):

```sh
sbatch install.sh
```

The environment goes to `$HOME/venv-gnn`. Override with `VENV=...` if needed.
Set `PYTHON_MODULE=python/3.11` if the default `python3` is older than 3.11.
Set `RECREATE=1` to rebuild.

The code uses the standard-library `tomllib` module. It needs Python 3.11 or
later. Check:

```sh
$HOME/venv-gnn/bin/python -c "import sys, numpy, pandas, scipy, torch, pymatgen; print(sys.version); print(torch.__version__)"
```

The experiment runs on CPU. A GPU does not help the small per-candidate graphs.

## 6. Run order

The order is strict. Do not open reserved labels before all checkpoints exist.

### Step 0 (optional) — run graphs and pools as short jobs

Both fit in 3 hours, so `normal` is enough. Submit as a chain so that prepare
starts only after graphs succeed:

```sh
graphs_id=$(sbatch --parsable --partition=normal --time=03:00:00 \
  --export=ALL,STAGE=graphs reference_baselines/cluster/reference_gnn.slurm)
sbatch --partition=normal --time=03:00:00 --dependency=afterok:"$graphs_id" \
  --export=ALL,STAGE=prepare reference_baselines/cluster/reference_gnn.slurm
```

### Step 1 — build the graphs

```sh
"$PYTHON" -m reference_baselines.graphs.build_reference_graph
```

Outputs `reference_baselines/results/reference_gnn/graphs/` with four `.npz`
files and `graph_report.json`. Check `status: passed` and
`candidate_labels_read: false`.

This step needs the fit rows and `candidate_decompositions.csv`. It also needs
the reference cosine arrays.

### Step 2 — prepare the candidate pools

```sh
"$PYTHON" -m reference_baselines.evaluation.reference_gnn --prepare --reuse-duplicates
```

This builds the validation and reserved pool tables for the four graphs and the
random control. It also builds the reserved duplicate table unless you disable
that step with `BUILD_RESERVED_DUPLICATES=0` (see section 7). It does not read
candidate labels.

The pool tables are compressed. Expect about 60 MB after the fit, validation,
and reserved tables are built. The main storage item is the 634 MB candidate
embedding array.

Outputs go to `results/reference_gnn/pools/` and `reserved/prepare.json`.

### Step 3 — train

Run once for each graph:

```sh
for graph in physical cosine self permuted; do
  "$PYTHON" -m reference_baselines.training.train_reference_gnn --graph "$graph"
done
```

This is 3 models (`gcn`, `gat`, `sage`) × 3 seeds × 4 graphs = 36 runs, up to
20 epochs each. `no_graph` remains available as an optional control, but it is
not in the default model list.

Each run writes:

```text
results/reference_gnn/runs/{model}_{graph}_seed{seed}/
  best.pt
  history.json
  complete.json
```

Checkpoint choice uses the lowest validation reference BCE only. A completed run
is skipped on restart. A partial run has no `complete.json`; delete that one
directory and rerun it.

### Step 4 — evaluate once

```sh
"$PYTHON" -m reference_baselines.evaluation.reference_gnn --evaluate
```

This opens the reserved labels after the frozen-checkpoint check passes.

Outputs in `results/reference_gnn/reserved/`:

```text
metrics.csv        passes and yield for every method and budget
comparisons.csv    paired 5% intervals against the original method
selections.csv     ranked candidate rows
checkpoints.csv    checkpoint hashes and validation BCE
evaluation.json    run record and source hashes
prepare.json       pool record
```

## 7. Environment switches for the cluster script

`reference_baselines/cluster/run_reference_gnn.sh` accepts:

| Variable | Default | Meaning |
| --- | --- | --- |
| `PYTHON` | `python` | Python binary in the environment |
| `STAGE` | `all` | `graphs`, `prepare`, `train`, `evaluate`, `all` |
| `BUILD_RESERVED_DUPLICATES` | `0` | `0` reuses the table; `1` rebuilds it |
| `DRY_RUN` | `0` | Print commands without running them |
| `GRAPH_ONLY` | empty | Train one graph only |

Examples:

```sh
STAGE=graphs bash reference_baselines/cluster/run_reference_gnn.sh
STAGE=prepare bash reference_baselines/cluster/run_reference_gnn.sh
STAGE=train GRAPH_ONLY=physical bash reference_baselines/cluster/run_reference_gnn.sh
BUILD_RESERVED_DUPLICATES=1 STAGE=prepare bash reference_baselines/cluster/run_reference_gnn.sh
```

### Slurm

NUS account and partition are set in the job script
(`--account=allusers --partition=long`). Submit from the repository root:

```sh
sbatch reference_baselines/cluster/reference_gnn.slurm
```

`normal` allows only 3 hours. The full job needs `long` (up to 3 days).

Logs go to `reference_baselines/results/logs/reference-gnn-%j.log`.

## 8. Failure handling

| Symptom | Action |
| --- | --- |
| `Missing graph ...npz` | Run Step 1 |
| `Incomplete run` | Delete that run directory and retrain it |
| `changed. Use a new results directory` | Config or split changed. Use a new `--run-dir` |
| `Reserved rows entered a non-reserved split` | Split files are wrong. Stop |
| `Legacy test rows are blocked` | The old test file is in a split. Stop |
| `cannot fill unique N% budget` | The duplicate rule removed too many rows. Report it |
| Out of memory | Lower `batch_size` in the config, then use a new run directory |
| Long runtime | Measure one seed on one graph before the full job |

If a job stops during training, resubmit the same command. Completed runs are
skipped.

## 9. What not to commit

- `embeddings/`
- `.vscode/`

- `reference_baselines/data/`

The results are data artifacts. Keep them on the cluster and copy them back
separately if needed.

## 10. Claims and limits

After the run, you may say:

- the model selects known references that match saved hull decompositions;
- the physical graph changed the fixed-budget pass count under the MatterSim
  proxy screen.

You must not say:

- the model predicts candidate stability;
- MatterSim proves DFT stability;
- the reserved split is an independent publication holdout;
- the method adds new crystals to the reference bank.
